# players channel group: EDA profile

Tome: `tomes/2026-10-01_to_08/tome/csds`, channels `basic_<name>.2026-09-18,2026-10-08`. Match universe = 1,752 keys in `header/dataframe_00000` (`key` column). Read-only; generated by `scripts/eda/profile_players.py`.

## Goofy list (ranked by how much each could mislead a model)

1. Duplicate matches leak across splits: player_info has 47 groups (99 matches) and team_change has 46 groups (97 matches) with identical content under different match keys, e.g. copies stamped 2026-10-08 18:08:58 and 18:09:22 UTC. The bakeoff reports the same 46 groups (97 matches) from its round_end and death events, with copies on both sides of the train/test split. Any match-level split or grouped CV will overstate scores.
2. Player identity is not recoverable: name, clan_tag, name_new, name_old and chat text are the literal 'redacted' in every row; steam_id is a single letter (19 values A-S), not a SteamID; player_id is a per-match slot 0-19 whose numbering disagrees with player_id_fixed on about 91% of player_info rows. Cross-match player keys are invalid.
3. Player count is not fixed at 10: 149 header matches are Wingman (is_wingman True), and 148 of them show only 4 player IDs. A further 271 matches show 11 player IDs in player_info, 263 with a header max_unique_players of 10 (likely bot slots). The bakeoff drops 3,663 rounds for player_count != 10, so this anomaly is already costing data.
4. player_sound covers 20 of 1,751 matches with rows (1.1%); all 20 are dated 2026-10-08. Rows per match run 6.6K-21.6K versus a median of about 200 elsewhere, and a zero-fill join reads 'no sound' as signal for 98.9% of matches. Within a tick, 23,967 excess rows repeat the same (match, round, player_id, tick) with different radius and duration; is_step is exactly duration == 0.5.
5. Spawn and team_change velocities include impossible magnitudes: 16,801 player_spawn rows (5.1%) exceed 10,000 units/s (max about 344,000), and 889 team_change rows do (max about 280,000). 6.5% of spawn rows exceed 250 units/s, while player_chat tops out near 258. player_phi_ang is exactly 90.0 in 67% of spawn rows and stays within 1-179.

## Definitions and checks run

- Null rate = nulls / rows. Distinct = distinct non-null values. Median over non-null, non-NaN values.
- Sentinel list: 4294967295, 65535, 32767, 2147483647, -1, 999, 9999 (numeric columns).
- Spike = one non-null value holds more than 20% of all rows in the channel (boolean and zero-heavy flags are expected here; read with care).
- Impossible-value rules are name-driven: health/armor negative or >100, money/cash negative or >16000, ammo/ping negative. Also negative radius/duration/wins/rank/elo/player_index and round or tick <= 0 are reported in 'Other checks'.
- Identical columns: pairwise null-aware equality across all non-all-null columns.
- Duplicates: full-row excess duplicates, and excess rows on (match_key, round, player_id[, tick]).
- Match row counts: per match, counted over matches with at least one row. The top-3 list ranks by |rows - median|. Zero-row matches are reported separately.
- One-to-one pairs: two columns with 2-20 distinct values where each value of one determines exactly one value of the other, in both directions (e.g. is_step and duration).
- Also checked: NaN/inf counts, empty or null-like strings, second vs tick/tick_rate, coordinate and speed ranges (horizontal speed > 250, 1000, 10000 units/s), z-position by map, phi/theta ranges, player_id vs player_id_fixed, distinct player IDs per match vs header max_unique_players and is_wingman, steam_id values, round vs header max_rounds, team swap rounds, match-key dates, schema types across channels.
- Interpretation notes: round values above header max_rounds (24) are overtime (contiguous, up to 48) and are expected. z_pos above 10,000 is only on de_vertigo, which is real map geometry. theta beyond +/-90 is expected for a yaw-like angle.
