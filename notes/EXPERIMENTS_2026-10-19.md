## What this is and how to read it

One list of every experiment, ablation and check the project has run: what each asked, how it was designed, what it found, the decision it led to, and where the results live. Nothing here is a new result.

- **Order.** Summary table of all experiments first. Then sections A to I (what the deck reports), J (earlier model history), K (other runs and checks that the deck does not report) and L (not run or open). Each section has a main table (ID, question, design, result, decision, source); detail tables follow the main table of the section.
- **Numbers.** Every number was copied by script from the file named in the Source column (field names in backticks; a date and time after a file name is its modification time). Where a file does not hold a number the text says "not recorded". A few differences were computed here and are marked "computed".
- **Metric and sign.** Per-second log loss on live seconds, lower is better. Every delta is variant minus reference, so a negative delta means the variant is better. Intervals are the 95% match-cluster bootstrap intervals stored in the `*ci95` fields (cluster_se_winprob_v3.json shows the match-cluster standard error is about 6 times the naive one). Validation decides settings; test is scored once.
- **Test sets.** The 58-, 59- and 60-input models are scored on the 2026 test matches: 3,059 matches, 3,956,374 seconds. The 13- and 14-input models are scored on all test matches: 3,601 matches, 4,568,043 seconds. Numbers from the two groups are not comparable with each other (see E41).
- **Decisions.** Taken from a `decision` or `adopt` field where a file has one; otherwise from the model metas, `notes/DELIVERABLE_2026-10-19.md` or `notes/GRILLME_FINAL_2026-10-19.md`, and the text says which. Labels: adopted, rejected, deferred, not run, running, reported only, superseded, check passed, plus exploratory, plumbing and check in section K. IDs follow the order in which the experiments were written up, so a few (E60 to E62) sit in a different section from their neighbours.
- **Open job.** No `exp_families_pistol.py` job was running at 2026-10-19 14:10. The LightGBM-only rerun finished and added the LightGBM validation interval (E36, O3). E37 (CatBoost CPU) and E38 (logistic) have no stride-3 result; full-set results for both exist in E39.
