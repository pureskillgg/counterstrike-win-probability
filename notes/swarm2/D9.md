# D9: match metadata and event hypotheses for the 2024 round-13 side mismatch

Owner: D9 (swarm2). Scope: 2024-02 tome only (`tomes\2024-02-g\tome\csds`, 4,435 matches). Read-only on the tome, bakeoff.py, extract_state_1hz.py and all existing outputs.

Scripts: `scripts\swarm2\D9_build.py`, `D9_tests.py` ... `D9_tests10.py` (plus `D9_schema_probe.py`, `D9_probe_keys.py`).
Logs: `logs\swarm2\D9_*.log`, `logs\swarm2\D9_crosstab_rushb.log`.
Intermediate tables (scratchpad, not the project): `D9_round.parquet`, `D9_match.parquet` under the session scratchpad `D9` folder.

## Bottom line

1. The defect follows the header field `build_num`. Build 9961 matches (2,478 matches) carry 434 of the 441 round-13 bomb rows that mismatch (98.4%). Build 9842 matches (1,957) carry 0 of 344. The effect survives control for match day: 12 days contain both builds, and the stratified permutation test gives p = 0.0005 (the floor for 2,000 permutations). Haldane-corrected Mantel-Haenszel OR = 618 over 12 day strata (no zero-cell correction needed to see the size).
2. `player_count == 20` is not an independent factor. All 499 mismatches are in pc20 rounds, but every round-13 round without pc20 (28 rows) is build 9842, and build 9842 has 0 mismatches in both pc20 and non-pc20 rounds. The pc20 signal is carried by build 9961.
3. Map is not needed to explain the defect. Within build 9961 and round 13, every map is 93-100% mismatched (de_ancient 47/47, de_anubis 42/42, de_dust2 16/16, de_inferno 62/64, de_mirage 122/122, de_nuke 56/56, de_overpass 21/21, de_vertigo 68/73). The raw map association (crude p = 0.068) is a build effect.
4. The mismatch is a labelling error in `round_end` winner, not in the bomb events. Two checks agree:
   - Bomb events are internally consistent (planter side 2 in 421 of 421 non-null round-13 mismatch rounds; defuser side 3 in 303 of 303 non-null defuse rows among mismatch rounds). 491 of 499 mismatch bomb events lie inside their own round's tick window (prev round end, own round end].
   - Death-based elimination check (independent of bombs): on non-bomb build 9961 round-13 rounds, the recorded winner is consistent with the deaths in 10.8% of rounds (198 of 1,838; recorded side passes), while the flipped winner passes in 86.9%. Build 9842 at round 13 passes at 95.2% as recorded. Rounds 25 and 28 show 0% recorded and 89.6% flipped.
5. The round-end win message agrees with the wrong winner code. In all 434 mismatch round-13 rows the message is generic (`Terrorists_Win` 313, `CTs_Win` 121), never `Bomb_Defused` or `Target_Bombed`. Matched round-13 rows with a bomb outcome use a bomb-specific message in 316 of 351 cases.
6. Duplicate groups, disconnects, bot takeover, match type, platform, and round-level event flags show no association with the mismatch once day is controlled. Details below.

## Population and reconciliation

Population P_main = bomb-outcome rounds with `round_end.player_count == 20` (same as `scripts\swarm\e2_side_check_r13.py`). Bomb outcome: `bomb_defused` gives side 3, `bomb_exploded` gives side 2, both from `basic_bomb_state`.

Reconciled exactly against `scripts\swarm\out\e2_side_check_r13.log`:
- P_main: 15,436 rounds, 499 mismatches (log: 15,436 / 499).
- Round 13 in P_main: 785 rows, 434 mismatches (log: 785 / 434; 605 rows days 12-25 plus 180 rows days 01-07, matching the brief).
- All bomb-outcome rounds regardless of player_count: 15,920 rows, 499 mismatches. The 484 non-pc20 outcome rows contain 0 mismatches.

Other facts from the probes:
- `round_end`: 83,527 rows; 83,526 unique (match, round). One (match, round) pair appears twice.
- `bot_takeover`: 0 rows and 0 columns in the 2024 tome. Cannot be tested.
- No `team_change` channel in the 2024 tome.
- Header: `match_type` = competitive for 4,432 matches, unknown for 3. `platform` = steam for 4,432, unknown for 3. `tick_rate` = 64 for all. `game` = csgo for all.

## Tests and verdicts

Method. Stratified permutation test: exposure labels permuted within match day (2,000 permutations), statistic = sum over days of Pearson chi-square. Mantel-Haenszel OR for binary exposures, strata = day. Crude chi-square shown for contrast. ASSUMPTION: day = match_key path day (`csds/2024/02/DD/`); the header `match_date` day agrees for only 1,550 of 4,435 matches (UTC timestamp), so the key day is used. ~25 tests, so the Bonferroni line is 0.002.

### D9-1: match_type and platform
- Only 3 "unknown" matches, 21 population rounds, 0 mismatches. Round 13 is 100% competitive and steam (785 rows).
- Verdict: refuted (no variation to test). Log: `D9_tests.log`.

### D9-2: build_num (9842 vs 9961), with rushb_version and game_build
- build_num, round 13, P_main: 9961 = 434 / 441 mismatched; 9842 = 0 / 344. Crude chi-square p = 1.1e-166. Within-day permutation p = 0.0005 (12 days with both builds). Haldane MH OR = 618 over 12 strata.
- Build 9961 is absent from days 01-07 and first appears on day 12. Days 12-25 contain both builds, so the test does not rely on a single day.
- Day 12: 9842 n=89 mm=0; 9961 n=96 mm=94. Day 16: 9961 n=41 mm=41. Day 25: 9961 n=28 mm=28.
- Build 9961 also mismatches on rounds 25 (24/24) and 28 (31/31) and round 9 (10/464). Build 9842 has 0 mismatches at every round index.
- rushb_version is a weaker proxy: 2.2.0 appears on 475 build-9842 matches (83 round-13 pc20 rounds on 9842, 0 mismatched). build_num separates the defect cleanly; rushb_version does not.
- game_build (from `game_directory` csgo_v2000xxx): round-13 mismatch 0% for 2000227-2000231, roughly 94-100% for 2000243-2000258. Consistent with the build split but finer, not needed.
- Verdict: SUPPORTED. Survives day control. Changes labels and model inputs.

### D9-3: map_name
- Crude across builds: p = 0.068 (round 13). Within build 9961, round 13 pc20: every map 93-100% mismatched (see Bottom line). Build 9842 maps have 0 mismatches.
- Verdict: refuted as a driver. The model does not need a map-specific fix for this defect.

### D9-4: player_count (pc20) and match_mixed_pc
- All 499 mismatches are pc20. Round 13 non-pc20 rounds: 28 rows, all build 9842, 0 mismatches. Build 9961 round 13 has no non-pc20 rows.
- Within-day permutation p = 0.0005 for pc20 round 13, but the test cannot separate pc20 from build (no build-9961 non-pc20 round 13 rows; pc20 build-9842 rounds also 0 mismatches). match_mixed_pc (round 13): 56 rows, 0 mismatches; those rounds sit in mixed matches that are build 9842.
- Verdict: explained by build (confounded), not an independent cause. Do not use player_count as a fix signal.

### D9-5: duplicate groups (bakeoff signature)
- 226 duplicate groups covering 522 matches; 296 non-lowest-key copies (174 build 9842 matches and 348 build 9961 matches in groups).
- All-round mismatch: is_dup_group within-day MH OR = 1.10, p = 0.047 (not significant at 0.002). Round 13: MH OR = 1.34, p = 0.089. non-lowest copies: MH 0.99, p = 0.26 (all) and 0.92, p = 0.24 (round 13).
- 48 round-13 duplicate groups with at least 2 copies carrying a round-13 outcome; 0 groups disagree on mismatch status. Dropping non-lowest copies leaves 391 of 719 round-13 mismatches, so dedupe does not remove the defect.
- Verdict: refuted as a cause. Duplicates are a separate data issue (already handled by bakeoff). Log: `D9_tests.log`.

### D9-6: disconnects and bot takeover
- dc_in_round (round 13): MH OR = 0.89, p = 0.44 (51 rounds with disconnect, 26 mismatched; 734 without, 408 mismatched).
- dc_in_match (round 13): MH OR = 0.62, p = 0.053, but the direction is opposite to the hypothesis: 22 rounds without a disconnect in the match had 15 mismatches (68%), vs 419 of 763 (55%) with one. Small n; not robust.
- dc_bot_in_round: 1 round in the whole population, 0 mismatches. bots_in_round: 0 rounds have a bot-flagged personal row.
- bot_takeover channel: 0 rows and 0 columns, so bot takeover cannot be tested.
- Verdict: refuted (no association; bot takeover untestable in 2024). Log: `D9_tests.log`.

### D9-7: round-level event flags
- five_v_five (all rounds): p = 0.0125 crude 0.76, MH OR = 0.79. Round 13: p = 0.088.
- no_round_start (all rounds): p = 0.20 within day. no_deaths and no_plant_row: no rows.
- planter team code null in 32 round-13 rows (13 mismatched); these are rounds with a bomb_planted row but null team code. Data-quality note, not a cause.
- Verdict: refuted as drivers. Log: `D9_tests.log`.

### D9-8: win_reason message as a signature
- Round 13, P_main: all 434 mismatch rows carry generic messages (Terrorists_Win on defused rounds 313; CTs_Win on exploded rounds 121). 0 mismatch rows use Bomb_Defused or Target_Bombed.
- Matched round-13 bomb rows: Bomb_Defused 272, Target_Bombed 44 (316 of 351 bomb-specific). The remaining 35 matched rows use generic messages.
- Verdict: SUPPORTED as a signature of the bad round_end records. Points at the round_end winner and message, not the bomb events. Log: `D9_tests.log` (D9-6 section).

### D9-9: death-based elimination check (independent of bomb events)
- Non-bomb rounds: recorded winner consistent with deaths (winner side's opponents all dead) vs flipped winner, by build and round index (`D9_tests4.log`, `D9_tests5.log`, `D9_tests8.log`):
  - Build 9842: round 13 recorded 95.2% (1,473 rounds), flipped 1.0%; round 25/28 recorded 96.2% (183 rounds), flipped 1.6%.
  - Build 9961: round 13 recorded 10.8% (1,838), flipped 86.9%; round 25/28 recorded 0.0% (192), flipped 89.6%; other rounds recorded 94.1% (36,324).
  - Build 9961 per round index (recorded): r9 0.80, r13 0.11, r25 0.00, r28 0.00, all other indices 0.89-0.97.
- The 7 build-9961 round-13 bomb rows that agree with the recorded winner have degenerate rosters (2 T and 2 CT in player_info), so the death check is uninformative there. A blanket flip would break them.
- Verdict: SUPPORTED. The round_end winner code is inverted on build 9961 at specific rounds.

### D9-10: which rounds are inverted (round-index structure)
- Build 9961, scored non-bomb pc20 rounds, per match (`D9_tests10.log`):
  - Round 13 flipped in 1,580 of 1,778 scored matches (88.9%).
  - Round 25 flipped in 88 of 88; round 28 flipped in 84 of 84.
  - Round 9 flipped in 294 of 1,873 (15.7%); 293 of those have no round-13 flip.
  - Exactly one flipped round in 1,794 matches; 2 flips in 50; 3 flips in 53; 0 flips in 544.
  - Most inversions are single rounds (round 14 and later are recorded correctly again).
- Interpretation (ASSUMPTION): the recorded winner is inverted on the first round after a side switch (13 in MR12, 25 and 28 in overtime). Round 9 is an unexplained secondary site in about 16% of build-9961 matches.
- Verdict: SUPPORTED as the scope of the defect. Round-index rule alone is not exact (round 9 and about 11% of matches with no round-13 flip).

### D9-11: bomb-event attribution (adjacent rounds and tick windows)
- Bomb outcome tick inside its own round's window (prev round end, own round end]: 491 of 499 mismatch rows, 14,380 of 15,421 matched rows (all rounds with an outcome). Round 13 mismatch: 429 of 434 inside.
- Adjacent-round check: the recorded winner of round 13 on build 9961 (n = 441 rows) equals the bomb-derived side of round 12 in 36 of 77 cases and of round 14 in 32 of 92 cases, i.e. no systematic match with a neighbour. No off-by-one shift in bomb events.
- Verdict: refuted (bomb events are not misattributed to adjacent rounds). Supports: the conflict is inside the same round window, in the round_end winner field.

### D9-12: round_start label offset (secondary, found while checking windows)
- For all 79,063 rounds with both a round_start and a round_end row, round_start(r) lies after round r's end and at or before round r+1's end (0 rounds start inside their own round). Every (match, round) group has exactly one round_start row (81,020 rows).
- Interpretation (ASSUMPTION): round_start rows are labelled one round early. round_state round_freeze_end is before its own round's end in all 83,382 rounds, and inside (previous round end, own round end] in all 78,947 rounds that have a previous round end (the other 4,435 are round 1).
- Impact: bakeoff.py step 3 drops rounds with "no round_start row"; with this offset, that filter drops the wrong rounds. The live window in bakeoff uses round_freeze_end, which is not affected. Not tested further here.
- Verdict: SUPPORTED (label defect in round_start). Log: `D9_tests3.log`, `D9_tests4.log`.

## What would fix the labels (if the hypothesis holds)

1. Scope: header `build_num == 9961` (the clean key; rushb_version is not). Build 9842 needs no correction (its round-13 and round-25/28 labels pass the death check at about 95%).
2. Bomb-outcome rounds on build 9961: set the winner from the bomb outcome (defused gives 3, exploded gives 2). This flips 434 of 441 round-13 rows (keeps 7), 55 of 55 round-25/28 rows and 10 of 464 round-9 rows. The bomb side is supported by planter and defuser team codes and by tick windows (ASSUMPTION: the bomb side is the truth when it is present).
3. Non-bomb rounds at round 13, 25, 28 on build 9961: flip the recorded winner only where the recorded side fails the death check and the flipped side passes. This is about 87-90% accurate on those rounds; treat the remaining ~10-13% as uncertain and exclude or flag them. Same check at round 9 (about 294 candidate rounds).
4. Re-run the side check after the fix: expect 0 mismatches on build 9961 bomb rounds, and non-bomb consistency near 94-95%.
5. Do not use `player_count` or `map_name` as a fix signal. Keep `build_num` as an audit field.
6. Separately: re-derive round_start round labels (shift by one) before any feature or filter uses round_start.
7. Check whether the 2026 tomes (0 mismatches per the brief) contain build 9961 matches; this swarm did not check that.

## Assumptions (all marked)

- ASSUMPTION: day = match_key path day (csds/2024/02/DD/).
- ASSUMPTION: bomb outcome side: defused -> 3 (CT), exploded -> 2 (T). Supported by planter team 2 and defuser team 3 in the non-null rows.
- ASSUMPTION: death-based consistency rule: winner side 2 needs all CT dead (CT_dead >= n_CT from player_info); winner side 3 needs all T dead (T_dead >= n_T). Victim side from player_death player_team_code. Baseline consistency on build 9842 is about 93-98%, so the rule is informative but not exact.
- ASSUMPTION: P_main = player_count == 20 (side-check convention).
- ASSUMPTION: round_start rows are labelled one round early (D9-12).
- ASSUMPTION: the swap interpretation for rounds 13, 25, 28 (D9-10).
- ASSUMPTION: is_bot flags are taken as recorded; no bot-flagged personal rows exist.
- Permutation p-values: 2,000 permutations; floor 0.0005. Bonferroni line for ~25 tests: 0.002.

## What could not be checked

- bot_takeover: 0 rows, 0 columns in 2024. Not testable.
- team_change: no channel in the 2024 tome. The halftime side switch cannot be read directly; the swap rounds were inferred from the round-index pattern and death consistency.
- Overtime past round 30: no rounds above 30 exist in this tome, so the swap rule could not be tested at round 31 onward.
- statsmodels is not installed in the project env, so no logistic regression; stratified permutation and Mantel-Haenszel were used instead.
- The round-9 subset (about 16% of build-9961 matches) has no identified mechanism here.
- The 2026 tomes were not checked for build 9961 matches.
- The fix in section "What would fix the labels" was not applied to any table; it is a recommendation only.
