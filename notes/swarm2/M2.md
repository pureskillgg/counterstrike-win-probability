# M2: map effect on CT win (swarm2)

Area: CT win rate by map, per era, and whether a map effect survives the alive difference and the live-start score lead.
Scripts: `scripts\swarm2\M2_build.py`, `M2_analysis.py`, `M2_scale.py`, `M2_selection.py`, `M2_raw_contrast.py` (plus probes `M2_header_probe.py`, `M2_schema_probe.py`, `M2_re_dup_probe.py`, `M2_cov_probe.py`, `M2_roster_probe.py`).
Logs: `logs\swarm2\M2_*.log`. Intermediate parquet and JSON are in the session scratchpad on C: (not in the project, nothing written under E:).

## Short answer

- A small map effect exists in-sample after controlling for the alive difference and the live-start score lead, with cluster-robust p = 0.010 (2026) and p = 0.0003 (2024). It replicates in direction across eras (per-map log-odds r = 0.85 on 5 shared maps).
- Its size is tiny: +0.00035 nats per state (2026) and +0.00030 (2024), about 0.15% of the alive-difference gain.
- Out of sample it adds nothing reliable: +0.00042 nats per state on the 2026 primary test (match-cluster 95% CI -0.00030 to +0.00115), and +0.00008 when fitted on 2026 and scored on 2024 (CI -0.00032 to +0.00045).
- Recommendation: do not add `map_name` as a model feature, and do not use per-map priors on the current data.
- The bake-off kept set is not map-neutral. Its filters remove 35% (2026 inferno), 46% (2026 vertigo) and 100% (2026 overpass) of those maps' rounds, and the removed rounds have higher CT win rates. The apparent inferno deficit in the kept set (-2.1pp in 2026, -2.3pp in 2024) shrinks to -0.5pp (CI includes 0) on raw rounds in both eras.

## F. Round-13 side defect: is it map-specific?

- 2026: 7,427 rounds with a bomb outcome, 0 mismatches (round 13: 308 with outcome, 0 mismatches).
- 2024: 15,920 rounds with a bomb outcome, 499 mismatches. Round 13: 813 with outcome, 434 mismatches (matches the open defect count in the brief). Non-round-13 mismatches: 65 of 15,107 in this count. (The brief's 41 of 14,602 uses only `player_count == 20` rounds.)
- Round-13 mismatch rate is spread across maps: mirage 60%, anubis 59%, vertigo 56%, inferno 55%, nuke 49%, dust2 48%, ancient 45%, overpass 38% (small counts for some).
- Excluding round 13 barely moves 2024 kept-set map rates: inferno 0.4882 to 0.4858, anubis 0.4804 to 0.4772, mirage 0.5235 to 0.5240, overpass 0.5118 to 0.5091.
- Map conclusions and the cross-era gain are unchanged when round 13 is excluded (section E).

## G. Other sensitivities

- 2026 kept set is all 24-round matches. The 149 header matches with `max_rounds = 16` contribute no kept rounds, so per-map rates are identical with a 24-round filter.
- 2026 raw data: 149 16-round header matches, `match_type` 'unknown' for 1,074 matches (not filtered by the bake-off; not analysed further).

## Findings (summary)

- M2-1 (medium): map effect survives the alive and lead controls in-sample but adds no reliable out-of-sample log loss. Recommend no `map_name` feature.
- M2-2 (high, conditional): the bake-off kept-set filters are map-dependent and create most of the apparent inferno deficit. Any map feature or per-map prior built on the kept set would inherit this bias.
- M2-3 (low): the round-13 defect is spread across maps and does not drive the map results.
- M2-4 (low): state-level LR tests overstate map significance; use cluster-robust tests.
- M2-5 (low): the 2024 kept set rests on assumptions, and the roster drop varies by map (7% to 18%).

## Assumptions (all marked)

- ASSUMPTION: live window = freeze-end to round_end; state definitions as in the bake-off.
- ASSUMPTION: bootstrap B = 2000, seed 0 (numpy default_rng for cluster bootstrap; Python random seed 0 for the primary split, same as bake-off).
- ASSUMPTION: map level threshold 20 kept matches per era; reference de_mirage.
- ASSUMPTION: 2024 full roster = player_count 20; 2024 max_rounds = 24 (flags only; not in map models).
- ASSUMPTION: CR1 small-sample factor on cluster-robust SEs; clusters = match.
- "Tied live start" probabilities assume alive difference 0 and lead 0.
- Score lead = freeze-end `ct_score - t_score` (bake-off feature, previously shown equal to the winner-derived lead on kept states).

## Limits (not done)

- No XGBoost or bake-off model refit with `map_name` added; this uses logistic regression only, as specified.
- Map-adjusted effects were estimated on the kept set only. No adjusted model on raw rounds (needs states for all raw rounds, incl. non-5v5 and partial rosters).
- Cause of the 2026 inferno and overpass `player_count != 10` exclusions was not investigated (no per-tick roster data checked). It may be outcome-related; not tested.
- 2024 roster drop (player_info with 4 or 9 players in about 14% of full-roster rounds) cause not investigated.
- 2024 kept set is not the bake-off set (no bake-off 2024 kept count exists in the notes I read). Its numbers are built under the assumptions above.
- Chronological split not run (2026 test window is one day, per earlier notes).
