Observations on the device checks:

- The conda-forge LightGBM build in this env is CPU-only (`cpu` in both package build strings). The CUDA message confirms that. The `device_type=gpu` path (OpenCL) reached OpenCL device enumeration (the Boost.Compute cache-path warnings), then aborted. The Windows Khronos OpenCL vendor registry key `HKLM\SOFTWARE\Khronos\OpenCL\Vendors` is absent. `nvopencl64.dll` and `nvopencl32.dll` do exist in `C:\Windows\System32\DriverStore\FileRepository\nv_dispig.inf_amd64_f4c7a2fd13e0f763`. I did not change any registry key or driver setting. Whether the missing key is the cause was not tested.
- CatBoost GPU works on the RTX 3080 when the VRAM reservation is capped. The default `gpu_ram_part=0.95` tries to reserve most of the free VRAM, which the shared card cannot provide. The working value in this run was 0.2 (ASSUMPTION, chosen by E2; 0.5 was not tested).

## 4. Benchmark design (ASSUMPTIONS marked)

- Same synthetic data for every engine: `numpy.random.default_rng(20241)`. Features are standard normal float32, `n_feat=50`. Target is Bernoulli of `sigmoid(f)`, with `f = X0 - 0.8*X1*X2 + 0.6*sin(2*X3) + 0.5*(X4>0)*X5 - 0.3*X6^2 + 0.2*X7`. ASSUMPTION: this structure is a stand-in chosen by E2. It is not CS2 data.
- Sizes: `n_train=100000`, `n_valid=50000`, `iters=100`, `repeats=2` (ASSUMPTION; chosen to fit the time budget under contention).
- CatBoost: depth 6, learning_rate 0.1, `loss_function=Logloss`, `border_count=128`, `random_seed=0`, `verbose=0`, `allow_writing_files=False`. CPU: `task_type=CPU`, `thread_count=1`. GPU: `task_type=GPU`, `devices=0`, `gpu_ram_part=0.2`, plus a 5-iteration warm-up on 20k rows that is timed separately.
- LightGBM: objective binary, learning_rate 0.1, num_leaves 63, max_bin 255, seed 0. CPU: `device_type=cpu`, `num_threads=1`. Dataset construction is timed separately from training.
- Timing: `time.perf_counter()` around fit (CatBoost fit includes its own quantization) and predict. Metric: validation logloss, computed in numpy with clipping at 1e-15.
- Sampler: a thread polls `nvidia-smi` (memory.used, utilization.gpu) and `GetSystemTimes` every ~0.5 s. WDDM hides per-process GPU memory, so the GPU fields describe the whole card, including the other jobs. The CPU field is whole-system busy %.
- Each configuration ran in its own process. Driver: `logs\swarm2\E2_bench_driver.log`.

### Reproducibility note

- CPU repeats gave identical logloss (LightGBM 0.559844 and CatBoost 0.552949, both reps).
- CatBoost GPU repeats with the same seed gave different logloss (0.548867 and 0.545308). The cause was not investigated. The GPU fit is therefore not bit-reproducible across repeats in this config, as observed.
- LightGBM and CatBoost logloss differ (0.5598 vs 0.5529 for CPU). The two engines use different tree structures and defaults. This is not an accuracy comparison.

## 6. Findings (E2-n)

- E2-1 (high): LightGBM GPU is not available in cs2gpu_alt. `device_type=cuda` is refused at build level, and `device_type=gpu` aborts natively. Training device plan: LightGBM stays on CPU unless it is built from source with `-DUSE_CUDA=1` or the OpenCL path is fixed. Neither was attempted.
- E2-2 (high): CatBoost GPU runs on the RTX 3080 (device 0, one GPU visible). It is fragile on this shared card. The default `gpu_ram_part` (0.95) aborted with CUDA OOM. `gpu_ram_part=0.2` also aborted once with CUDA OOM (17:01) and then succeeded on retry (17:10). Plan: use CatBoost GPU with an explicit `gpu_ram_part` and a retry wrapper, or wait for the other GPU jobs to finish.
- E2-3 (medium): Under the observed contention, CatBoost GPU was slower than CatBoost CPU at 1 thread for this size: median fit 31.788 s vs 20.241 s. Timing comparisons are not reliable while the machine is at 100% CPU.
- E2-4 (medium): LightGBM and CatBoost CPU baselines should use 1 thread on this machine under load. LightGBM slowed sharply with more threads: 0.586 s at 1 thread, 2.039 s at 2, 17.004 s at 4 (about 29x) for 20 trees on 20k rows. With 16 threads the same size took 70.263 s.
- E2-5 (medium): LightGBM CPU (1 thread) fit median 10.85 s vs CatBoost CPU (1 thread) 20.24 s on the same synthetic data. The two engines also reach different validation logloss (0.5598 vs 0.5529). Speed comparisons should be made with matched tree settings on an idle machine.
- E2-6 (low): CatBoost GPU repeats with the same seed gave different validation logloss (0.548867 vs 0.545308). CPU repeats were identical. Not investigated.
- E2-7 (low): WDDM hides per-process GPU memory, so the nvidia-smi sampler cannot attribute VRAM to CatBoost. The memory deltas (0 to +213 MiB) are not usable as evidence of allocation size. Utilization spikes are the only in-run evidence of GPU work.

## 7. Limits and what was not done

- Not tested: LightGBM built from source with CUDA or OpenCL, and any change to the Khronos OpenCL registry key.
- Not tested: CatBoost or LightGBM on real CS2 data. All numbers are synthetic (see Section 4).
- Not tested: XGBoost CUDA. The project env's xgboost 3.4.2 CPU build was not touched.
- Environment changes: only `C:\Users\13144\envs\cs2gpu_alt` (new pixi workspace) and its global install under `C:\Users\13144\.pixi\workspace-envs\cs2gpu_alt-*`. The project env `G:\pureskill\csds-cs2\.pixi` was not modified.
