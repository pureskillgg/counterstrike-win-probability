## Corrections to the request

- `--max-concurrent-requests` is not a flag on `aws s3 sync`. It is the config key `s3.max_concurrent_requests`, default `10` (OPENED, s3-config topic). The sync reference page does not list it (OPENED).
- The multipart settings are config keys too, not per-command flags: `s3.multipart_threshold` (default `8MB`) and `s3.multipart_chunksize` (default `8MB`; the page states a `5MB` minimum for uploads) (OPENED).
- No resume option appears on the sync reference page (OPENED, by absence in the extracted page). I did not find a `--continue`-style flag in any page I opened.
- `--expected-size` is not on the sync reference page as extracted. I did not open the `aws s3 cp` page.
- `--query` is client-side JMESPath output filtering, not a download filter (OPENED, cli-usage-filter page). Do not confuse it with `--include` and `--exclude`.

Default copy rule, from the page's examples (OPENED): a file is transferred when the sizes differ, when the source last-modified time is newer, or when the object is missing at the destination. For S3-to-local downloads, "The default behavior is to ignore same-sized items unless the local version is newer than the S3 version." Checksums are not part of this comparison. The page describes checksums only through `--checksum-mode` and `--checksum-algorithm`.

## 3. Resume, checksums, and byte ranges

- **No resume flag** on the sync reference page (OPENED, absence).
- Practical resume (my inference from the OPENED comparison rule, not from a doc): re-running the same `sync` skips objects whose size and last-modified time already match. A partly written local file would normally differ in size and be re-copied. I did not verify partial-file handling in any page.
- Byte-range fetches (OPENED, performance guidelines): "Using the `Range` HTTP header in a GET Object request, you can fetch a byte-range from an object... Fetching smaller ranges of a large object also allows your application to improve retry times when requests are interrupted." The page gives no numeric part size. The CLI exposure of this (for example a `--range` option on `s3api get-object`) was not opened.
- S3 checksum algorithms (OPENED, checking-object-integrity page): `CRC64NVME` (stated as the default for checksum calculations), `CRC32`, `CRC32C`, `SHA1`, `SHA256`, `MD5`, `XXHASH64`, `XXHASH3`, `XXHASH128`, `SHA512`. The page says "The `CRC64NVME` checksum algorithm is the default checksum algorithm used for checksum calculations."
- The page says the MD5 checksum must be provided via `x-amz-checksum-md5`, and that "AWS SDKs do not automatically calculate MD5 checksums."
- `--checksum-mode` on sync verifies stored checksums on download when present (OPENED). The value to pass was not in the extracted text, so confirm with `aws s3 sync help`.

## 4. Requester Pays and subscriptions

Requester Pays, S3 (OPENED, RequesterPaysBuckets page):
- "the requester instead of the bucket owner pays the cost of the request and the data download from the bucket. The bucket owner always pays the cost of storing data."
- "If you enable Requester Pays on a general purpose bucket, anonymous access to that bucket is not allowed."
- Requester must send `x-amz-request-payer: requester` (REST) or `--request-payer` (CLI).
- Charge goes to the bucket owner when a request "returns an `AccessDenied` (HTTP `403 Forbidden`) error and the request is initiated inside the bucket owner's individual AWS account or AWS organization."
- If the requester assumes an IAM role, "the account to which the role belongs is charged for the request."

Downloading from Requester Pays (OPENED, ObjectsinRequesterPays page):
- Response header `x-amz-request-charged:requester` on success.
- Without the header, S3 returns 403 and charges the bucket owner.
- CLI: "you specify `--request-payer requester` as part of your `get-object` request."

Data Exchange, S3 data access subscriptions (OPENED, subscribing-to-S3-data-access page):
- "Providers have the option to enable Requester Pays... If enabled, subscribers pay to read, use, transfer, export, or copy data into their Amazon S3 buckets."
- "AWS Data Exchange automatically provisions an Amazon S3 access point and updates its resource policies to grant you read-only access."
- IAM must allow `GetObject` and `ListBucket` on the provider bucket and the access point.
- Encrypted data needs `kms:Decrypt`. "AWS KMS grants can take up to 5 minutes" to become effective.
- "The data provided is stored in the provider's Amazon S3 bucket... you'll be responsible for the cost of the request and the data downloaded... unless the provider specifies otherwise."
- The provider's Requester Pays setting is visible on the access-point information in the console.
- Subscribe-time "Offer auto-renewal" toggle (OPENED).

Subscription and transfer charges (SNIPPET only): standard S3 rates apply to cross-Region import or export of file-based assets; exports through signed URLs are billed at internet transfer rates (search results from the Data Exchange pricing page). I did not open the pricing page, so no rates are given.

## 5. Data Exchange export to S3 and limits

Subscriber export steps (OPENED, export-rev-s3-console-sub page): Entitled data, then the product, then the data set, then the Revisions tab. Select the revision, choose "Export to Amazon S3", pick a destination, configure encryption, choose Export. The job's State becomes "Completed". The page gives no key naming, no charges, and no cancel steps.

Export and import guidelines (OPENED, Data Exchange user guide limits page, https://docs.aws.amazon.com/data-exchange/latest/userguide/limits.html):
- Revisions per `ExportRevision` job to S3: **1**.
- Assets per `ExportRevision` job to S3: **10,000**.
- Assets per cross-Region `ExportRevision` job: **10,000**.
- Cross-Region revision export size: **1,000 GB**.
- Event actions per resource: **5**. Per account: **50**.
- `SendApiAsset`: **10 TPS** per Region.

General Reference quotas (OPENED, https://docs.aws.amazon.com/general/latest/gr/dataexchange.html):
- Asset size in GB: **100 GB**, not adjustable.
- "Asset per export job from Amazon S3": **100**, not adjustable.
- Concurrent in-progress jobs to export revisions to Amazon S3: **5**.
- Concurrent in-progress jobs to export assets to Amazon S3: **10**.
- Assets per revision: **10,000**, adjustable.
- Revisions per data set: **10,000**, adjustable.
- Auto export event actions per data set: **5**, adjustable.
- Event actions per account: **50**, adjustable.
- Amazon S3 data access assets per revision: **5**, adjustable. Revisions per Amazon S3 data access data set: **5**, adjustable.

Conflict to resolve: the user guide gives 10,000 assets per `ExportRevision` job to S3, but the General Reference row "Asset per export job from Amazon S3" gives 100 (not adjustable). The two may refer to different job types, which I could not confirm. Check the Service Quotas console for the Data Exchange service before planning around either number. A third-party snippet said 10 concurrent export jobs to S3. The OPENED General Reference gives 5 for revision exports and 10 for asset exports, so use the OPENED values.

## 6. Application to a targeted September 16 to 30 pull

Mechanism (this is a template; the key layout was not inspected, so replace the placeholders):

```
aws s3 sync "s3://<bucket>/<prefix>/" "<local_dir>/" --dryrun --exclude "*" --include "<pattern_for_2026-09-16_to_30>"
```

- Run the dry run without `--only-show-errors`. The page says `--only-show-errors` suppresses "All other output", which would hide the preview lines that `--dryrun` prints (inference from the two OPENED descriptions).
- Then run the same command without `--dryrun`, adding `--only-show-errors` and optionally `--no-progress` for log hygiene.
- Concurrency is a config key, for example `aws configure set default.s3.max_concurrent_requests 20` (the example pattern is OPENED; the value 20 is my choice). The page says to raise it "to use more network bandwidth" and lower it "on constrained systems".
- Do not add `--delete` to a filtered pull without a dry run first. `--delete` removes destination files that are not in the source (OPENED). I did not verify how filters and `--delete` interact.
- `--page-size` (default 1000, OPENED) can speed listing of very large prefixes. I did not measure this.
- If a requester-pays bucket is involved, add `--request-payer requester`. The option name is on the sync page (OPENED). The value `requester` is OPENED for the get-object CLI and the REST header.
- Data Exchange file exports are one revision per job (OPENED). Several revisions need several jobs.
- For S3 data access subscriptions (OPENED), the access point alias can replace the bucket name in the sync command. Check IAM first.

Whether a 15-day window helps the model is a modelling question, not a download question. My judgment: with about 230k states from about 1,500 matches, adding matches is more likely to help than narrowing the date range, but this should be tested, for example by training on the slice and on the full set. I did not verify this against any source.
