# CS2 position embedding and win-probability architectures

Date: 2026-10-22. Stage 2 deliverable (position embedding and match rendering).

Source: the four family surveys supplied to this step (set encoders; graph and relational models; self-supervised position and trajectory embeddings; neural and calibration-first win-probability models). No new searches were run. A paper appears here only if one of those surveys lists it.

## Constraints this document assumes

- Ten player slots per state. Positions are one-second samples of living players only. Dead players are absent from the stage 2 files, so they need a mask (from `STAGE2_PLAN_2026-10-22.txt`).
- One model per map, starting with de_mirage.
- Evaluation must use match-grouped splits. No surveyed paper does this (see below).
- Metric is log loss, with calibration checked by ECE and tail checks.

## How to read the tables

- **verified: yes.** The paper's record was opened (landing page, arXiv, DOI or OpenAlex) and the cited claim was checked against it, as the survey states.
- **verified: no.** Seen only in search results, or the publisher page was blocked. Not relied on.
- **(summary)** The numbers come from a WebFetch summary of the HTML version, not from the PDF table. Re-check before quoting.
- **(abstract)** Only the abstract was read. No table numbers are claimed.

Important: no surveyed paper reports log loss on a match-grouped CS split. Each number below comes from a different data set, split or metric, so none is a benchmark for this project. Log loss is unitless. The log base is not stated in ESTA or in the 2022 Xenopoulos and Silva paper.

## 3. Recommendations

### 3a. Positions-only embedding: pick E1, a masked set encoder

**Recommendation.** Build the positions-only embedding as a permutation-invariant set encoder (E1, Deep Sets form) over the ten slots, one model per map. Each slot contributes (x, y, z, alive flag, side) through one shared MLP. Dead players are masked out of the pooling. Pool with sum, mean or max and pick by test. Keep the embedding positions-only. Add alive counts, team HP, economy and bomb state only in the head.

For dead players, use a masked slot with an alive flag (the plan's default), not the last known position. The surveys support alive flags as inputs and near-zero attention for dead players (Xenopoulos and Silva 2022, verified: yes). No survey supports last-known positions, which would put stale coordinates into the set.

**Reasons.**

1. The data is already a masked set. Only living players appear, one sample per second. Masked pooling handles a variable count directly. An ordered-slot autoencoder has to learn a fixed slot-to-player map and cannot drop a missing player cleanly.
2. Order invariance is the one property the surveys support across several families (Deep Sets, PointNet, Set Transformer, and the graph pooling in Xenopoulos and Silva 2022; all verified: yes). The stage 2 slot order is a convention, so the embedding should not depend on it.
3. The other candidates have weaker evidence. Contrastive positives leak the outcome or learn adjacency (E7). Word2Vec-style embeddings have one unreplicated accuracy gain (E5). Masked transformers have no outcome metric in the surveys (E6), though they are the next experiment if E1 underfits.
4. The surveys show set encoders can lose. In ESTA, Deep Sets was level with LightGBM and behind the MLP on about 132 to 289 demos per map (verified: yes; summary). de_mirage alone has 3,416 matches. The units differ (demos vs matches), but the sample is roughly an order of magnitude larger, so the test can go either way. Let the acceptance test decide.
5. A positions-only embedding carries no economy, role or count information. Xenopoulos and Silva show the state branch is what makes the graph model best (GAT alone 0.4465 vs GAT+State 0.4276). Treat the embedding as a feature next to state, not a replacement.

**Acceptance test (to be run, not assumed).** Use match-grouped folds. Report log loss with standard error over repeated seeds, in the style ESTA uses, plus ECE. Use a state-only MLP as the reference. Keep the embedding only if it beats the reference by more than the seed standard error.

### 3b. Win-probability model: calibrated state MLP, with a GBDT as the check

**Recommendation.** Use a feedforward MLP on engineered state features: alive count per side, team HP, equipment value, bomb state, round time, map, and simple geometry such as distance to sites. Train on match-grouped splits. Calibrate with temperature scaling on a separate match-grouped holdout. Run a gradient-boosted tree on the same features as a required second baseline. Add the positions embedding (H3) only if it passes the test in 3a. Use an additive model (W1, H2) only where a per-feature audit is required.

**Reasons.**

1. The strongest evidence is for state-only vector models. In ESTA the MLP was best on all seven maps, and LightGBM was within about 0.02 log loss (verified: yes; summary). Any embedding must beat this reference.
2. The best graph result improves the state baseline by 0.0075 log loss on one split, with no variance reported (Xenopoulos and Silva 2022, verified: yes). That does not justify a deep model without a stronger test.
3. Calibration is the failure mode the surveys warn about. Neural heads need temperature scaling and tail checks (C1). This is one parameter and cheap to fit.
4. The one CS model with time (Szmida and Toka 2026, verified: yes) beat logistic regression by about 0.01 log loss on Inferno, but its split is not described and it uses 114 matches. It is a later option (R3), not the first model.
5. Serving cost: a state MLP or GBDT is cheap on CPU. No surveyed paper reports serving cost for a win-probability model. The 0.5 ms figure in Durst et al. (verified: yes) is for movement, not win probability.
6. The stage 2 sampling rate (one sample per second) matches the setup in Xenopoulos and Silva 2022 (one state per second, 14,291,069 states). Their numbers are the closest scale comparison, but they are not comparable because the data, years and splits differ.

**Caveat.** These recommendations come from the surveys only. The project's current win-probability model and its results were not read for this document, so this does not say whether the recommendation beats or replaces what is already built.

## 4. One line on a single deep model for everything

A single deep model for embedding, win probability and action valuation is not supported: the cleanest head-to-head comparison (ESTA, verified: yes) has the deep set models behind a plain MLP and GBDT, the best graph gain is 0.0075 on one split, and the one temporal model describes no match-level split, so keep the deep encoder as a component behind a calibrated head.
